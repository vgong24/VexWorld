# Character Asset Intake — Stage C

`[VXG RealForever]`

**Architecture ref:** `architecture.vexworld.character-asset-intake/v1`

## Why this exists

A useful rig or animation pack can accelerate adapter learning, but it must never quietly become VexWorld's character identity, narrative persona, capability model, or permanent technical dependency.

The intake route is therefore intentionally asymmetric:

```text
official source evidence
→ exact candidate record
→ optional quarantine download
→ artifact hash
→ exact license / rights review
→ structure analysis
→ semantic topology / socket / intent mapping
→ replacement proof
→ independent review
→ accepted reference/expression input OR rejection
```

A brand-level statement such as “this creator usually publishes CC0” is not artifact provenance.

## Truth classes

```text
RESEARCHED_NOT_DOWNLOADED
  official source may be known; bytes are not local

QUARANTINED_EXACT_ARTIFACT
  exact bytes are local but have no accepted runtime authority

LICENSE_AND_RIGHTS_REVIEWED
  exact artifact rights have been checked

STRUCTURE_ANALYZED
  rig/topology/material/animation facts may be described

SEMANTIC_ADAPTER_MAPPED
  source structure is mapped into VexWorld-owned semantics

REPLACEMENT_TEST_PASSED
  canonical refs survive substitution

ACCEPTED_REFERENCE_STRUCTURE_ONLY
  may teach/prove adapter structure; not a canonical visual dependency

ACCEPTED_EXPRESSION_INPUT
  may be used as a declared replaceable expression dependency

REJECTED / SUPERSEDED
  not used as an active dependency
```

## Exact intake receipt

An accepted candidate must preserve at least:

```text
assetCandidateRef
exactPackageName
sourcePublisherRef
officialSourceUrl
artifactVersionOrRelease
officialArtifactUrlOrAcquisitionRoute
downloadedAt
sha256
licenseSpdxOrExactIdentifier
licenseSourceUrl
permittedUseSummary
attributionRequirement
redistributionAndModificationNotes
localQuarantinePath
formatInventory[]
rigAndAnimationFacts[]
modificationRecordRefs[]
semanticMappingRefs[]
replacementProofRef
disposition
reviewReceiptRef
```

Unknown values remain unknown. They are not filled with inferred precision.

## Character-specific review

A candidate is rejected or held when its use would require VexWorld to inherit a distinctive protected character identity, story persona, brand-dependent silhouette, or unreplaceable runtime convention.

Structural learning is narrower:

```text
bone hierarchy shape
joint orientation
socket opportunities
animation intent coverage
material slots
mesh segmentation
export format behavior
```

These facts may help design an adapter when the exact rights permit the intended use. They do not authorize copying the expressive identity of a proprietary character.

## Replacement is part of acceptance

For an accepted expression dependency, prove:

```text
same participant / resident / lineage ref
same vesselRef
same relevant semantic topology
same required action / animation-intent surface
same inventory / practice / save-state references
+ different expression asset or VexWorld-owned substitute
= continued valid world participation
```

If removing the downloaded asset would erase who the character is, the architecture has failed.

## Stage C initial posture

The first Stage C source fixtures are original procedural VexWorld expressions. This keeps the semantic grammar independently testable while provenance research runs in parallel through `github.issue.vexworld.17`.

No external artifact is accepted by this document or by being named in the candidate registry.
