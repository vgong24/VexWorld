# VexWorld build graph

The machine-readable source is `config/build-graph.json`.

## Completion-state-first direction

The historical build graph records how First Grove and its reusable foundations were proven. It is not a claim that VexWorld itself is a linear game campaign or that every future world must repeat the same implementation order.

VexWorld now carries an explicit completion-state source:

```text
docs/architecture/SHARED-WORLD-COMPLETION-STATE.md
```

Future programs should ask:

```text
what mature shared-world capability must eventually exist?
-> which source should own that meaning?
-> what is the smallest bounded proof needed now?
-> what accepted foundations can be reused?
```

rather than:

```text
what is the next game feature in one scripted sequence?
```

## Accepted Version 1 trajectory

The accepted reference-realm trajectory established reusable foundations through:

```text
source foundation
→ compiler
→ headless realm
→ browser First Grove prototype
→ party/controller bindings
→ trusted-LAN checkpoint and companion relay
→ synchronized techniques / World Witness
→ offscreen/headless continuity
→ dimensional portability
→ Devex practicum
→ read-only physical shadow
→ Chronicle / replay / worldlines
→ World Memory
→ cinematic/media continuity
```

Those are reusable capabilities, not a requirement that all future VexWorld experiences be adventure games.
