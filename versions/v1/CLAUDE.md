# VexWorld Version 1 cold-start and contributor instructions

`[VXG RealForever]`

## Ground before acting

Inspect the checkout without mutation:

```bash
git status --short
git branch --show-current
git remote -v
git log -1 --oneline
```

If a remote exists, fetch before making current-state claims. Do not continue an inherited non-main branch unless an exact handoff identifies its owner, purpose, base, and expected head.

## Read in this order

When entering from repository root, read root `CLAUDE.md` and `config/current-version.json` first. Inside Version 1, continue:

```text
1. README.md
2. vexworld.manifest.json
3. this file
4. config/source-map.json
5. docs/CULTURE.md
6. docs/ARCHITECTURE.md
7. docs/DEVEX-BUILDER-GUIDE.md
8. only the exact sources/tests implicated by the current task
```

Do not reconstruct the project by broad repository archaeology when the source map names an exact door.

## Current architecture route

```text
project ledger / current position: VexWorld issue #3
project culture and product foundation: VexWorld issue #1
CTO architecture atlas: VexWorld issue #2
```

Issue prose does not prove source implementation. Live repository source, generated fingerprints, tests, exact candidate heads, and accepted receipts outrank stale status wording.

## Development loop

```text
desired experience or question
→ locate semantic owner
→ declare bounded change and non-effects
→ define or update a scenario
→ change canonical source
→ regenerate derived outputs
→ execute deterministic/headless proof
→ playtest when applicable
→ classify discrepancy at the correct layer
→ review exact candidate
→ accept, revise, split, reject, or park
```

Run before handing off:

```bash
npm run check
npm run demo:headless
```

For visual work, also run the browser game and inspect the actual rendered experience. A passing test does not prove fun, clarity, accessibility, or visual quality.

## Effect boundaries

This repository may implement fictional-world source, simulation, browser presentation, and bounded LAN-development adapters. It does not independently authorize:

```text
physical actuation
real-world professional authority
production identity/security claims
public economy or payments
private-memory extraction
model weight mutation
unreviewed live code generation
third-party asset copying
```

When a task crosses identity, memory, safety, economy, physical embodiment, or federation authority, descend to the exact upstream Vextreme owner and preserve the return route.

## Clean-repository proportionality

VexWorld should not import heavyweight multi-lane ceremony merely because it exists elsewhere. Use one clear effect owner, small reviewable stages, source-grounded tests, and recipient-complete handoffs. Add coordination machinery only when actual concurrency or conflict earns it.

## Local Home boundary

The root launcher stores local session state in `%USERPROFILE%\.vexworld` on Windows or `~/.vexworld` on Mac. Do not commit Home contents, local tokens, model artifacts, or private play history.
